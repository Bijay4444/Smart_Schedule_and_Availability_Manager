The scheduling app is deployed on an Azure Ubuntu virtual machine. Caddy handles HTTPS, Gunicorn serves Django, and PostgreSQL stores schedules in persistent volumes. Separate settings support local and production environments. This single-server design fits the demonstration. Backups are supported, but there is no automatic failover, and the new local features still need deployment.

Smart Schedule / Final seminar09 / 11
GitHub Actions tests pull requests and deploys successful pushes to main. It builds and rehearses a Docker image, then deploys that exact tested image. Before migrations, it takes a database backup. It checks application health and public HTTPS before reporting success. Azure access uses OpenID Connect, and temporary SSH firewall access is removed afterward. The linked run records an earlier successful deployment; it does not claim today's uncommitted additions are live.

Demo participants should be able to create their own account. Google and GitHub OAuth signup are now implemented alongside password login. A first provider sign-in creates a private account; returning identities reuse it. Accounts are not automatically merged just because emails match. The screenshot is a local preview with both providers configured. Public use still requires registering the provider apps, setting credentials, deploying the release, and rehearsing real sign-ins. Until then, the shared fictional guest account remains the demo fallback. Sign out also stays reachable on short laptop screens.
